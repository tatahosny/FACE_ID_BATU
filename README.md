## 🌟 نظرة عامة (Overview)

منظومة إلكترونية متكاملة، فائقة الأمان والاعتمادية، مخصصة لإدارة وتنظيم عمليات تسجيل بصمة الوجه وتنسيق طوابير الحضور لطلاب الفرقة الثانية بقسم تكنولوجيا المعلومات في **جامعة برج العرب التكنولوجية**.

توفر المنظومة بيئة تشغيلية تفاعلية تعتمد على أحدث معايير الأمان وتوزيع الصلاحيات، وإدارة الشبابيك المزدوجة (`شباك T` و `شباك D`)، وتنظيم حضور الطلاب بدقة لمنع التكدس، مع نظام معالجة غير متزامن فائق التطور يرسل إشعارات التيليجرام لحظة بلحظة مع حماية كاملة من الحظر.

## 🚀 الإصدار 3.1: ملخص التحديثات الكبرى (Version 3.1 Highlights)

يمثل **الإصدار 3.1** قفزة نوعية في استقرار واعتمادية المنظومة، حيث تم حل جميع مشاكل الضغط العالي، التزامن، ومشاكل الإشعارات والتسجيل بشكل جذري:

### 1. ⚡ محرك الإرسال الذاتي التلقائي في الخلفية (Autonomous Background Dispatcher)
- **معالجة غير متزامنة 100% (Detached Execution):** تم فصل عمليات إرسال رسائل التيليجرام تماماً عن طلبات الـ HTTP وعن المعاملات البنكية لقاعدة البيانات (Transactions) عبر معالج غير متزامن يعمل في الخلفية (`setImmediate`). الاستجابة في الموقع أصبحت تتم خلال **أقل من 50 ميلي-ثانية**.
- **فاصل زمني آمن ومنتظم (Safe Throttling 40ms - 60ms):** يضمن إرسال الرسائل بمعدل آمن يتراوح بين **~16 إلى 25 رسالة/ثانية**، وهو المعدل الذهبي الذي يحمي البوت من تجاوز حدود التيليجرام الرسمية.
- **التعامل الذكي مع حظر التيليجرام المؤقت (`429 Too Many Requests`):** يقوم المعالج بقراءة قيمة `retry_after` التي يطلبها تيليجرام بدقة وينتظر انتهاءها ثم يستأنف التدفق تلقائياً دون سقوط أو فقدان أي رسالة.

### 2. 📊 نظام كشوف استلام الرسائل وتقارير التقييمات الشاملة (`/admin/ratings`)
- **كشف استلام حي ومفصل (Delivery Report Modal):** نافذة منبثقة تفاعلية في لوحة التقييمات تتيح استعراض حالة استلام كل طالب (تم التسليم بنجاح ✅ / في الانتظار ⏳ / تعذر التسليم ❌).
- **متابعة المقيمين ومعدل الاستجابة:** عرض من قام بالتقييم الفعلي مع درجات التقييم (1 إلى 5 نجوم) وملاحظات الطلاب، مع إمكانية البحث الفوري بالاسم أو الرقم الأكاديمي والفلترة الدقيقة.
- **أزرار سريعة في كل كارت حملة:** زر يوضح عدد الطلاب الذين استلموا الإشعار فعلياً (`{عدد} استلموا 👁️`).

### 3. 🎯 التنبيه المتدرج للأدوار والطابور الذكي (Multi-Tiered Queue Milestones)
تم استبدال التنبيه المفاجئ بنظام إنذار تدريجي ذكي متعدد المراحل لكل شباك (`شباك T` و `شباك D`):
1. **`PROXIMITY_15` (متبقي 15 دوراً):** تنبيه استباقي بمتابعة الطابور والاقتراب من المقر.
2. **`PROXIMITY_10` (متبقي 10 أدوار):** تنبيه بالتوجه إلى مبنى الشؤون (الواحة).
3. **`PROXIMITY_5` (متبقي 5 أدوار):** تنبيه عاجل بالوقوف أمام الشباك المخصص فوراً.
4. **`PROXIMITY_NEXT` (أنت التالي مباشرة):** تنبيه بالاستعداد لدخول بصمة الوجه.
5. **`TURN_CALLED` / `REPEAT_ALERT` (حان دورك الآن):** نداء رسمي مع رقم الدور والشباك المخصص وتنبيه الحضور الفوري.
6. **مفاتيح منع التكرار (`idempotencyKey`):** حماية كاملة تضمن عدم إرسال نفس المرحلة لنفس الطالب أكثر من مرة لنفس الحجز.

### 4. 🔄 الاسترداد والتحديث الذكي لحسابات الطلاب (Smart Profile Reclaiming)
- القضاء التام على خطأ `"البيانات مسجلة بالفعل"` الذي كان يحبس الطلاب ويمنعهم من التسجيل أو تعديل سكشنهم.
- إذا كان الطالب مسجلاً مسبقاً في النظام وأدخل رقمه الأكاديمي ورقمه القومي الصحيحين، يتعرف عليه النظام فوراً ويقوم **بتحديث سكشنه ومجموعته وقيده فوراً** وتوليد رابط ربط تيليجرام صالح لمدة 15 دقيقة، وتسجيل دخوله بنجاح.
- **التطبيع التلقائي للأرقام العربية (Arabic Digits Normalization):** تحويل الأرقام المكتوبة من لوحات مفاتيح الهواتف الذكية (`٠١٢٣٤٥٦٧٨٩`) إلى الصيغة القياسية (`0123456789`) آلياً لمنع أي خطأ في المطابقة أو التشفير.

### 5. 🛡️ حل مشكلة تأخير الـ 10 أدوار (`bookings_window_desk_queue_idx`)
- تحويل الفهرس `bookings_window_desk_queue_idx` من قيد فريد (`UNIQUE`) إلى فهرس ترتيبي مرن، مما سمح بتبديل وتدوير أرقام الأدوار بحرية تامة دون أي تعارضات في المفاتيح.
- صياغة استعلام التبديل الذري باستخدام التحويل الصريح للـ UUID (`id = ${id}::uuid`) لضمان التوافقية التامة مع محرك PostgreSQL تحت أي ضغط تشغيلي.

### 6. 🧹 تصفية الرسائل المتأخرة وحماية الساعتين (Freshness Guard)
- تم تصفير وإلغاء **97 رسالة قديمة متراكمة** في جدول الصادر (Outbox) وتحويل حالتها إلى `CANCELLED`، بحيث يبدأ النظام من الرسائل الجديدة فقط دون إزعاج الطلاب بإشعارات قديمة.
- **قيد الحماية الزمني (2-Hour Freshness Guard):** أي إشعار يمر عليه أكثر من ساعتين في الانتظار يتم إلغاؤه فوراً وتلقائياً لضمان حداثة البيانات دائماً.

### 7. 🚫 المعالجة الذكية لحسابات التيليجرام المحظورة (Blocked Bot Handling)
- التعرف الفوري على أخطاء خوادم التيليجرام الدائمة:
  - `Forbidden: bot was blocked by the user` (الطالب قام بحظر البوت).
  - `Bad Request: chat not found` (الطالب لم يبدأ محادثة مع البوت).
- وسم الرسالة بـ **`FAILED` نهائي فوري** دون إهدار محاولات إعادة الإرسال ودون إبطاء الطابور لبقية الطلاب.

## 🏢 الهيكل الأكاديمي والشبابيك (Academic & Desk Architecture)

### 1. نظام الشبابيك المزدوجة (Dual-Desk Radar):
- **شباك بصمة الوجه T (Desk T)**: مخصص لخدمة طابور البصمة بتوزيع دوري.
- **شباك بصمة الوجه D (Desk D)**: شباك موازٍ لامتصاص الضغط ومضاعفة سعة الاستيعاب.
- **التوجيه التلقائي بالتناوب (Round-Robin Auto-Balancing)**: يتم توجيه الطلاب تلقائياً بالتناوب العادل بين الشباكين عند حجز الدور لمنع التكدس على شباك واحد.

### 2. التقسيم الأكاديمي:
- **الفرقة الدراسية**: الفرقة الثانية — قسم تكنولوجيا المعلومات.
- **المجموعات الأكاديمية**:
  - المجموعة الأولى (`G1`) — السكاشن (1، 2، 3، 4)
  - المجموعة الثانية (`G2`) — السكاشن (1، 2، 3، 4)
  - المجموعة الثالثة (`G3`) — السكاشن (1، 2، 3، 4)
- **الأقسام الفرعية**: تقسيم كل سكشن إلى قسمين فرعيين مستقلين: **قسم A** و **قسم B**.

## 🛠️ البنية التقنية (Technology Stack)

- **الواجهة الأمامية والخلفية**: [Next.js 14](https://nextjs.org/) (App Router, Server Actions & Route Handlers)
- **لغة التطوير**: TypeScript (Strict Type Checking)
- **قاعدة البيانات**: PostgreSQL سحابية مدعومة بمحرك تجميع الاتصالات (Connection Pooling)
- **مخطط ومحرك البيانات**: [Drizzle ORM](https://orm.drizzle.team/)
- **التصميم والواجهات**: Tailwind CSS، خط Cairo العربي الرسمي، دعم كامل للاتجاه من اليمين إلى اليسار (RTL) والأوضاع الليلية التفاعلية
- **محرك الأيقونات والتنبيهات**: Lucide React
- **معالجة المستندات**: مكتبة XLSX لتصدير ملفات الإكسيل المتقدمة مزدوجة الشيت

## 💻 متطلبات التشغيل المحلي (Getting Started)

### 1. تثبيت الحزم والمكتبات:
```bash
npm install
```

### 2. تجهيز ملف البيئة (`.env`):
قم بإنشاء ملف `.env` محلي يحتوي على متغيرات التكوين الخاصة ببيئة التشغيل (بيانات اتصال قاعدة البيانات والمفاتيح السرية للتطبيق وتوكن بوت التيليجرام).

### 3. تشغيل خادم التطوير:
```bash
npm run dev
```

افتح المتصفح وتوجه إلى `http://localhost:3000` للوصول إلى واجهة المنظومة.

### 4. بناء نسخة الإنتاج والتحقق البرمجي:
```bash
npx tsc --noEmit
npm run build
npm run start
```
