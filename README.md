# 🏛️ BATU FACE ID Registration & Queue Management System
### المنظومة الذكية لتسجيل البصمة وإدارة الطابور المركزي — جامعة برج العرب التكنولوجية (BATU)
**قسم تكنولوجيا المعلومات — كلية تكنولوجيا الصناعة والطاقة**

---

## 🌟 نظرة عامة (Overview)

منظومة إلكترونية متكاملة، فائقة الأمان والاعتمادية، مخصصة لإدارة وتنظيم عمليات تسجيل بصمة الوجه وتنسيق طوابير الحضور لطلاب الفرقة الثانية بقسم تكنولوجيا المعلومات في **جامعة برج العرب التكنولوجية**.

توفر المنظومة بيئة تشغيلية تفاعلية تعتمد على أحدث معايير الأمان وتوزيع الصلاحيات، وتنظيم حضور الطلاب بدقة لمنع التكدس، مع إرسال إشعارات فورية وتنبيهات ذكية لحظة بلحظة.

## ✨ أحدث التحديثات والمميزات المطورة (New Updates & Features)

### 1. 🎟️ تعميم وتوحيد أرقام التذاكر لجميع سكاشن المنظومة (Unified Global Ticketing)
- **عداد تذاكر موحد للنظام ككل**: أرقام التذاكر تبدأ من رقم 1 وتستمر تصاعدياً بصيغة موحدة (`001`, `002`, `003`...) لجميع المجموعات والسكاشن، بدلاً من وجود عداد منفصل لكل سكشن يسبب تكرار نفس رقم التذكرة لأكثر من طالب في نفس اليوم.
- **الانضمام لنهاية الطابور العام (Strict FIFO Queue)**: عند فتح أي فترة حجز جديدة لأي سكشن أو قيام طالب بإعادة الحجز، ينضم الطالب مباشرة إلى نهاية الطابور العام للنظام لضمان العدالة والأسبقية المطلقة لمن حجز أولاً.

### 2. 🔀 التخصيص الدقيق لفتح الحجز حسب القسم الفرعي A و B (Sub-Section Targeting)
- **تحديد القسم المستهدف**: يمكن للمشرف عند فتح فترة الحجز لأي سكشن اختيار السماح بالحجز لـ (`قسم A فقط` أو `قسم B فقط` أو `القسمين معاً A & B`).
- **ضوابط حجز صارمة**: الطلاب المنتمون لقسم فرعي غير مسموح له بالحجز يتم منعهم فوراً مع إظهار رسالة واضحة توضح أن الحجز متاح للقسم الآخر فقط.
- **إشعارات موجهة**: إرسال إشعار فتح الحجز حصرياً لطلاب القسم الفرعي المستهدف دون إزعاج باقي طلاب السكشن.

### 3. 🔄 نقل زر تصفير الأدوار إلى شاشة الطابور الحي وحمايته (End-of-Day Queue Reset)
- **إلغاء التصفير من فترات الحجز**: تم إلغاء زر تصفير الأدوار نهائياً من صفحة إدارة فترات الحجز لمنع التصفير الخاطئ أثناء اليوم الدراسي.
- **زر نهاية اليوم المركزي**: نُقل زر التصفير إلى أعلى شاشة الطابور الحي (`تصفير التذاكر لـ 1 (نهاية اليوم)`) لإعادة تعيين التذاكر لتبدأ من 001 لجميع سكاشن المنظومة لليوم التالي.
- **صلاحية حصرية**: الزر محمي بالكامل ويظهر حصرياً لحساب المشرف العام (**Super Admin**)، ومخفي تماماً عن حسابات الموظفين.

### 4. 📍 المقر المعتمد المتغير لإشعارات البصمة (Dynamic Activation Location)
- **تحكم كامل للمشرف العام**: إمكانية تعديل وتحديد «المقر المعتمد» للجان البصمة من لوحة إعدادات النظام في أي وقت.
- **إدراج ديناميكي في الرسائل**: يتم جلب المقر المعتمد تلقائياً في سطر `المقر: ...` داخل رسالة التهنئة والاعتماد الرسمية المرسلة للطالب فور تفعيل بصمته، دون وجود أي نصوص ثابتة.
- **خيارات سريعة ومعاينة حية (Live Preview)**: توفير مقترحات سريعة للمقرات والمعامل المعتمدة مع شاشة محاكاة حية لشكل رسالة التيليجرام تتحدث لحظياً أثناء الكتابة.

### 5. 🔔 التنبيه التلقائي لاقتراب الدور والتقدم الحي (Live Proximity Alerts)
- **تنبيهات اقتراب الدور**: إرسال إشعارات تلقائية للطلاب عند وصول دورهم إلى (10 أدوار متبقية) ثم (5 أدوار متبقية) للحضور أمام المقر في الوقت المحدد.
- **تحفيز الطابور الحي**: بمجرد اعتماد بصمة أي طالب في شباك البصمة، يقوم النظام آلياً بفحص الطلاب المنتظرين وإرسال إشعارات التقدم اللحظي للطلاب التاليين في الطابور.
- **آلية تأخير غير الحاضرين**: إمكانية تأخير الطالب المتغيب 10 أدوار للخلف لإعطاء الفرصة للمنتظرين مع تحديث حالته لحظياً.

### 6. 📊 تطوير شامل لدليل الطلاب المركزي (Advanced Student Directory)
- **بطاقات إحصائية تفاعلية**: إحصائيات لحظية تعرض إجمالي المسجلين، البصمات المعتمدة، قيد الانتظار، بالإضافة إلى عداد مخصص للموظف المحدد وتاريخ الاعتماد المختار.
- **فلاتر متعددة ومتقدمة**: إمكانية تصفية دليل الطلاب بدقة حسب (المجموعة، السكشن، القسم الفرعي A/B، حالة اعتماد البصمة، الموظف الموثق، وتاريخ التوثيق).
- **إلغاء البصمة وإعادة فتح الحجز (Bidirectional Activation Control)**: إمكانية قيام المشرف العام بإلغاء اعتماد بصمة طالب مفعل وإلغاء دوره، مما يتيح له حجز دور جديد من البداية.
- **الحذف الفردي والمجمّع (Single & Bulk Delete)**: دعم ميزات حذف طالب محدد نهائياً أو تحديد مجموعة طلاب عبر Checkboxes وحذفهم دفعة واحدة من دليل الطلاب (محصورة بالسوبر أدمن).
- **تصدير كشف Excel احترافي مزدوج الشيت (Dual-Sheet Export)**:
  - **الشيت الأول**: الكشف العام الشامل لجميع الطلاب مع الأرقام القومية والأكاديمية والسكاشن.
  - **الشيت الثاني**: كشف مستقل ومفروز يقتصر حصرياً على الطلاب الذين تم اعتماد وتفعيل بصمتهم رسمياً.

### 7. 🛡️ نظام الصلاحيات الصارم وحجب الصفحات الإدارية (Strict Multi-Role RBAC)
- **مسؤول النظام العام (Super Admin)**:
  - تحكم كامل وغير مقيد في جميع إعدادات المنظومة، السكاشن، فترات الحجز، حسابات الموظفين، وسجلات التدقيق.
  - الصلاحية الحصرية لتفعيل وإلغاء البصمة، حذف الطلاب، تصفير التذاكر، وضبط المقر المعتمد.
- **طاقم عمل وموظفو البصمة (Staff)**:
  - **حجب 10 صفحات إدارية بالكامل**: إخفاء صفحات فترات الحجز، الجداول، المجموعات، السكاشن، حملات التيليجرام، القوالب، الإشعارات، حسابات الموظفين، سجلات التدقيق، والإعدادات من القائمة الجانبية مع نظام حماية وتحويل تلقائي فوري للمسارات (Route Guards).
  - **صلاحية استعراض فقط بدليل الطلاب**: حظر أزرار تفعيل البصمة، وإلغاء البصمة، وحذف الطالب، وإخفاء مربعات التحديد وشريط الحذف المجمّع.
  - **شاشة الطابور الحي**: حظر وإخفاء زر تصفير التذاكر مع قصر عمل الموظف على نداء الأدوار وتسجيل الحضور المباشر.
- **بوابة الطالب (Student Portal)**:
  - استعلام مباشر وسهل عن حالة الحجز ومواعيد الحضور وجدول المواعيد المعتمد.

## 🛠️ البنية التقنية (Technology Stack)

- **الواجهة الأمامية والخلفية**: [Next.js 14](https://nextjs.org/) (App Router & Server Actions)
- **لغة التطوير**: TypeScript (Strict Type Checking)
- **قاعدة البيانات**: PostgreSQL سحابية مدعومة بمحرك تجميع الاتصالات (Connection Pooling)
- **مخطط ومحرك البيانات**: [Drizzle ORM](https://orm.drizzle.team/)
- **التصميم والواجهات**: Tailwind CSS، خط Cairo العربي الرسمي، دعم كامل للاتجاه من اليمين إلى اليسار (RTL) والأوضاع الليلية التفاعلية
- **محرك الأيقونات والتنبيهات**: Lucide React
- **معالجة المستندات**: مكتبة XLSX لتصدير ملفات الإكسيل المتقدمة

## 💻 متطلبات التشغيل المحلي (Getting Started)

### 1. تثبيت الحزم والمكتبات:
```bash
npm install
```

### 2. تجهيز ملف البيئة (`.env`):
قم بإنشاء ملف `.env` محلي يحتوي على متغيرات التكوين الخاصة ببيئة التشغيل (بيانات اتصال قاعدة البيانات والمفاتيح السرية للتطبيق).

### 3. تشغيل خادم التطوير:
```bash
npm run dev
```

افتح المتصفح وتوجه إلى `http://localhost:3000` للوصول إلى واجهة المنظومة.

### 4. بناء نسخة الإنتاج:
```bash
npm run build
npm run start
```
